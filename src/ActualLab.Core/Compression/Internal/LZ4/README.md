# Vendored LZ4 (K4os.Compression.LZ4)

The LZ4 block codec, streaming (chained) encoder and decoder from
[K4os.Compression.LZ4](https://github.com/MiloszKrajewski/K4os.Compression.LZ4)
(MIT license, (c) 2017 Milosz Krajewski), copied into `ActualLab.Core`. Only the
fast (non-HC) compressor and the decompressor are here. All types are `internal`;
the public API is `LZ4ByteCompression`, `LZ4ByteCompressor` and `LZ4ByteDecompressor`
in `ActualLab.Compression`.

## Origin

- Upstream commit: `67701f7` (master, "chore: cleanup").
- Plus the preset dictionary support (`LZ4FastDictionary`, the dictionary-aware
  `LZ4FastChainEncoder` / `LZ4ChainDecoder` constructors, `Reset()` and
  `Reset(dictionary)`): upstream PR
  [#122](https://github.com/MiloszKrajewski/K4os.Compression.LZ4/pull/122),
  branch `feature/fast-dictionary` of `ActualLab/K4os.Compression.LZ4` at `81555b8`.
  Once it's merged (or changed in review), re-sync from upstream.

## Changes made while copying

- Namespaces: `K4os.Compression.LZ4.Engine` / `.Internal` became
  `ActualLab.Compression.Internal.LZ4.Engine` / `.Internal`, the rest
  `ActualLab.Compression.Internal.LZ4`.
- Every type is `internal`; each file starts with `// <auto-generated/>`,
  `#nullable disable` and `#pragma warning disable`, so the analyzers skip it.
- `LLxx` lost its HC (`LZ4_compress_HC*`) entry points.
- `LL32.*.cs` are generated from `LL64.*.cs` upstream (a header plus
  `#define BIT32`); keep them in sync the same way.

## Updating

Check upstream for new commits touching the files here, port them, and update the
commit above. Keep the code as close to upstream as possible, so ports stay easy.
